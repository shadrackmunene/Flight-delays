## 4. Handling policy

| Situation | Treatment |
|---|---|
| Blocking rules: `dq_bad_date`, `dq_missing_key_field`, `dq_invalid_crs_dep_time`, `dq_invalid_cancel_flag`, `dq_invalid_diverted_flag`, `dq_cancelled_and_diverted`, `dq_exact_duplicate` | Row kept in the cleaned file with `analysis_include = FALSE`; excluded from KPIs and models. |
| Warning rules | Row kept and included; flag available for sensitivity analysis. |
| Negative delays | Preserved (early departures/arrivals). Never clipped or flagged on their own. |
| `2400` in an HHMM field | Interpreted as 00:00 (valid BTS spelling of midnight). |
| Invalid HHMM (hour > 24, minute > 59, non-integer) | Set to NULL and flagged; the raw delay value is kept. |
| Overnight flights | Dates are the scheduled departure date. `sched_dep_ts`/`actual_dep_ts` are built from date + minutes, so a departure delayed past midnight lands on the next calendar day. `sched_crosses_midnight` marks flights whose scheduled arrival falls on the next day. |
| Cancelled / diverted flights | Own `outcome` value; kept in the table and excluded only from arrival-delay classification and arrival-delay KPIs. |
| Missing values on cancelled flights | Expected (no departure/arrival occurred); see section 6. |
| Empty trailing column | Dropped from the cleaned output only after the count in section 2 shows how many cells held data. |
